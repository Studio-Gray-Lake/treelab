# TreeLab

Grow low-poly trees in your browser, compare their variations, and see how they look in a forest on hills, swaying in the wind. Save your settings, share a link or a screenshot, and download the trees as a model. TreeLab is a free tech demo from Studio Gray Lake. Its trees, wind and sway come from the studio's 3D Procedural Animation Workshop.

**Play it: https://studiograylake.com/treelab/**

No accounts, no cookies, and TreeLab itself sends nothing anywhere: your settings stay in your browser, and the address holds a link to what you see. The copy on studiograylake.com also loads the site's visit counter (Cloudflare Web Analytics, no cookies); a copy you build or run yourself has none.

After five minutes, once a visit, a small card in the corner asks whether you'd like to support the studio on Ko-fi. It's a plain link with Ko-fi's own button picture, kept in TreeLab's files: no Ko-fi script, and nothing loaded from Ko-fi. "Never show this again" is kept in your browser, and so is the fact that this tab has already shown it. Nothing else is kept, anywhere.

## Run it

```bash
npm install
```

```bash
npm run dev
```

Then open http://localhost:5180.

```bash
npm test
```

The tests must show `ℹ fail 0`. They grow trees and read the shaders as text; none of them draws a picture. This does:

```bash
npm run check:browser
```

It serves TreeLab, opens it in a browser with no window (Chrome or Edge, whichever the computer has; `CHROME_PATH` names another), checks that the welcome card opens on a first visit and that OK closes it, then shows each starting view in turn and checks that nothing went wrong (no error, no shader that won't compile, no complaint from the graphics card), that there is a picture (not one flat colour, black or burnt out) and that the trees are there. A picture of each is left in `.scratch/browser-check/`. Whether a view looks right is still for eyes.

TreeLab has no motion clips of its own: the figure moves by hand-keyed cycles. It can be fitted with clips from [Mixamo](https://www.mixamo.com/) on your own computer. Download them there as .fbx, without skin (the walk and the run with *in place* ticked), into a `.mixamo/` folder in TreeLab's folder, named `Walking.fbx`, `Running.fbx`, `Jump.fbx` and `Idle.fbx`, then:

```bash
npm run bake:clips
```

It writes `.mixamo/figureClips.js`: each clip's motion fitted to the workshop's figure (its legs by where the ankles are, every other bone by how it's turned from rest), cut to start as the left foot lands, with its speed over the ground read from its feet. A clip that isn't there is left out, and the figure keeps its hand-keyed cycle for it. When that file is there, `npm run dev` and `npm run build` use it in place of the empty `src/figureClips.js`; a build made for the site (`npm run build:site`) never does. Neither Mixamo's own files nor the clips fitted from them are part of TreeLab: `.mixamo/` and every `.fbx` are kept out of git.

```bash
npm run build
```

builds the site into `dist/`. To serve it from a sub-folder of a website, set `TREELAB_BASE` (say `/treelab/`) when building; by default the paths are relative, so `dist/` works from any folder. `npm run build:site` builds the copy for studiograylake.com: the same, plus the site's visit counter (`/assets/analytics.js`).

## Where the trees come from

TreeLab runs on copies of eight files from the 3D Procedural Animation Workshop, in `vendor/workshop/`:

| File | What it does |
|---|---|
| `treeShapes.js` | The tree generator: each kind's settings, the skeleton, the wood and foliage |
| `treeSway.js` | Each tree a spring bent by the wind, and the shader that bends it |
| `spring.js` | The damped spring `treeSway.js` uses |
| `wind.js` | The wind: mean wind, gusts, swirl, lee behind hills, calm under crowns |
| `windView.js` | The wind as a texture for the shaders, and its debug view |
| `ik.js` | A leg bent to put its ankle where it's asked (hip, knee, ankle): for the figure's walk |
| `gamepad.js` | A game controller read through the browser: sticks, triggers, buttons |
| `rig.glb` | The workshop's character, built in Blender: the figure that stands by the trees for scale, and walks the forest |

The workshop is their only home: **never edit the copies here**. Change them in the workshop, then copy them again:

```bash
npm run sync
```

`vendor/workshop/SOURCE.json` records when they were copied, and each file's hash. `tests/vendor.test.js` fails if a copy was edited in TreeLab, if one starts importing something TreeLab doesn't copy, or (where the workshop is checked out) if the workshop has changed since the last sync.

To try a workshop change before syncing it, run TreeLab on the workshop's own files:

```bash
npm run dev:live
```

To tell TreeLab where the workshop is, put the path of its `src` folder in a `.workshop` file in TreeLab's folder (git ignores it), or set `WORKSHOP_SRC`. The workshop itself isn't public, so on a public clone there's nothing to sync from: the copies are all you need. The page says which files it's reading, under the stats, while developing.

## Using it

Two tabs, one set of settings.

- **start from** (the panel's first row): a whole starting point, every setting at once. *one oak* is TreeLab as it opens, *mixed forest* the same on the Forest tab, *oak and underwood* an English wood as it stood in the Middle Ages, tall oaks over hazel, hawthorn and a few hollies, *beech wood* a wood of tall forest-grown beeches in autumn, copper leaves over smooth grey trunks in a morning sun, and *misty wood* a wood of tall oaks early in the morning, fog on the ground, seen from among the trees: the sun is low and ahead, so its light falls in shafts between the trunks, with the *light shafts* setting at 1, as in life. A starting point is only settings: change anything and the row says *custom*.

- **The English oak** is TreeLab's own tree, grown at its real size (a mature oak in the open is about 20 m tall and wider than that). Its branches grow into the space of an oak's crown and compete for it, so they branch unevenly and from all along their parents; every branch is as thick as the branches it carries, and a side branch starts thinner than the one it leaves. Its leaves grow only where there's light for them. The clusters of leaves are taken from the top down, and each keeps its leaves if enough of the sky's light reaches its underside through its own leaves and those above it (an oak's leaves live on about 8% of full light and stop light as measured in real oaks): so the crown is a layer of leaves at its top and outside, with fewer under it, fewer still further in and down, and bare limbs inside; sky shows through from underneath (6 to 8% of it; real crowns show 7 to 24%), and the shade is dappled by real gaps. Among neighbours (*neighbours*) the low sky is hidden, and the leaves are at the top only. Only twigs still growing carry leaves: a twig off the side of a branch that has since run on many times as far as the twig ever grew stopped long ago, shaded out as the crown closed over it, and is bare, so few clusters sit low down and deep inside. Every cluster sits on its twig, drawn from the wood into its middle: none floats. A slider changes what it names and nothing else: each part of the tree has random numbers of its own, and every oak is grown as the usual oak of its seed and then fitted to its own height, crown width and bare trunk, so those three stretch the tree and regrow nothing, one more limb leaves the others where they were, and a fuller crown keeps its limbs and its lean (where the crown itself changes, its finer branching rearranges with it). A crown bigger than the usual settings grow gets more of everything (branches, wood, clusters), up to three times as much for a 35 m oak, where it used to be the 20 m oak's skeleton stretched. It is drawn by its own mesher. Its wood is round (three sides for a twig, up to 24 for an ancient trunk); a branch is thicker where it leaves its parent, and wood thins gradually toward and past a fork; thick limbs are curves through their steps. Its foot spreads toward the ground, most where a root leaves it, and the roots run out over the ground: a third of each in it, rising and dipping on the way (here riding high, there under and out again), a long one forking, each going under for good over its last third. They're gnarled where they're thick, as the trunk is. (They lie on level ground: on a slope they don't follow it yet.) Its trunk bends a little on its way up (*bends*: none at the ground, where it's rooted, and the crown goes with it). It can be gnarled (lumps and flutes), carry burrs (bulges) and hollows (deep dents, dark inside, with a raised rim: dents, not holes through to a cavity), and it and the big limbs carry dead stubs, pale where they broke, where twigs died long ago. Those marks come with age and gather low down, as an oak's do: a trunk's thickness is its age, so a thin trunk shows few and a thick one many (as many as its sliders say at 0.6 m), and they're thickest at the foot and thin out with height (*marks reach up*: 0 at the foot only, 1 evenly all the way). So a tall thin forest oak has a clean bole, and a short thick one in the open is marked all over. Thick wood is drawn with an uneven mesh (no rows of diamonds), and a limb with sides about as wide as its trunk's. Where each mark is comes from the tree's own chance, so none moves when another slider does, and none of them changes the branches or the leaves. Its leaves are drawn as masses: each limb's clusters of leaves merged into billowing surfaces; lumps of many sizes run together, a mass is hollow underneath, so the branches show from below. (They began as a ball a cluster; the balls are gone.) *Merging* (0 to 100%, 70 as it starts) is how many of the clusters near enough to run together do: at 100 a bough is one mass, lower down some clusters stay masses of their own, which overlap the others and move by themselves as the bough bobs, and at 0 every cluster is its own (raising it only adds merges: the ones made stay); *leaves reach* is how far a cluster's leaves reach toward its neighbours, so how far apart two can be and still run together (more reach also makes every mass a little fuller); *noise* (0 to 200%) shapes the masses with 3D noise, from the round lumps as they are (0) to bent, billowing ones that open where they run thin (100), never putting leaves where there is no twig; what the noise is like is chosen in a folded panel of its own (*noise*, in the crown's section): its *type* (smooth swells; creased: puffs with sharp creases between; ridged: sharp ridges; cells: round clumps), the *size* of its broad billows, how many finer layers lie on them (*detail*), how far it pulls the shapes out of round (*bend*) and how strongly it thickens and thins the leaves (*billow*); a layer of noise finer than the facets fades out, since it can't be drawn; and *coarseness* sets the facets' size. Its crown's outline can be drawn (*crown → outline*): a picture of the crown from the side with five dots, at its bottom, each quarter of the way up and its top; drag a dot in or out (or use the row under the drawing) to set how far the branches reach there. The branches follow, since they grow into that space, and the trunk carries on up toward where the crown is widest, so the limbs of a crown that's widest high up leave it all the way up and not in a bunch. The ready-made oaks each have their own: the open-grown oak's broad dome (which is what every oak had before), a young one's narrow egg, a forest oak's crown wide only near the top, an ancient one's low flat spread. Its *age* (years, the first slider) moves the others in plain sight: to an oak's of that age, grown in the open, between a young one at 15, a grown one at 150 and an ancient one at 500 (the ready-made oaks), and on past them from 10 to 800. Its thickness and its marks go by the years (wood is laid on year by year, and burrs and hollows come late); its height, its crown's width and outline, its bare trunk and its limbs by the age's logarithm (a tree does most of its growing up and out early), so an oak of 50 is about 13 m tall on a trunk 44 cm across, and one of 800 is lower than in its prime and 3.6 m across. Any slider can be moved by hand afterwards; the age itself grows nothing. (What neighbours do to a tree, the forest-grown oak, isn't an age: the slider doesn't know it yet.) In a forest the trees of each kind are of several ages (*mix → oak of several ages*, ticked to start with for every kind of TreeLab's own; untick it and they are all of the age the Tree tab shows): each of the forest's oak shapes (*variants a kind*: six to start with, up to twelve) has an age of its own between the youngest and the oldest asked for (*oak ages*), spread evenly by the age's logarithm since a tree changes most while it's young (*young to old* leans them either way), and is the Tree tab's oak at that age, with whatever was changed by hand there carried along (a crown made half as wide again is half as wide again at every age). The info card lists the ages. An oak's age sets its size, so the forest's *size* varies such oaks a third as much. Its sliders reach well past any real oak (50 m tall, a trunk 3 m thick, limbs sagging to the ground, sixteen burrs), so the outlying ones can be looked at. They are an oak's, in sections by the part of the tree: size (age, height, crown width, lean), trunk (bare trunk, thickness, bends, gnarl, burrs, hollows, marks reach up), roots (flare, surface roots), limbs (big limbs, crooked, sag, dead stubs), crown (fullness, neighbours, the outline's own panel, cluster size, flat to tall, lumpy, merging, leaves reach, coarseness, and the noise's own panel: amount, type, size, detail, bend, billow) and movement (sway). *start from* gives an oak grown in the open, a young one, one grown in a forest, and an ancient one. The workshop's broadleaf, fir and pine are there too, as the workshop grows them.
- **The beech** is TreeLab's second broadleaf, grown by the same code as the oak, by its own settings: 24 to 30 m in the open, a dense dome nearly as wide as it's tall on a short trunk, with more limbs than an oak, the upper ones steep, the lowest sweeping out and down and turning up at their tips (*tips turn up*); branches that curve where an oak's zig-zag; leaves in flat layers; smooth, pale grey bark with hardly a mark on it; shallow roots out over the ground. It has an *age* slider and four ready-made shapes: *young* (slim and pointed, with a clear leader), *open-grown*, *old* (thicker far more than taller, its lowest limbs to the ground) and *forest-grown* (a clean column, bare for half its height and more, with a narrow crown at the top). Its leaves are the oak's merged masses, with every one of the oak's settings. Four of those came with the crown forms, and every broadleaf of TreeLab's own has them: *cluster width* (how many times wider a cluster's leaves are drawn than the light allows it), *runs together* (limb by limb, or the whole crown: whether the leaves of different limbs run into one mass) *leaves along branches* (how many of the twigs off a branch's side keep their leaves: at 0, leaves sit only at the branches' ends) and *ends hang* (how far the leaves at a branch's end hang below their twigs, and how much longer they are for it). Its crown has a form, the first row of its crown's rows (*crown form*): *layered dome*, as it starts (flat layers, spread wide, running together across the limbs, which add up to one dome), or *cushions*, as it was (rounder clusters, limb by limb). A form sets six of the rows below it together, in plain sight; a link made before the dome opens with cushions. Its layers are the clusters set flat (*flat to tall* 0.42) and drawn wider than they grew (*cluster width* 1.25), not a way of growing of its own, and they lie level where a real beech's follow their boughs: said plainly. A grown one is about 22,500 triangles.
- **The hawthorn** is a small tree, grown by the same code as the oak, by its own settings: 6 to 9 m, a dense round crown about as wide as it's tall, on a short trunk that leans, bends and is fluted (*gnarl*) on far less wood than an oak's; its branches a tangle. It is the first of the trees of medieval England's woods, where it stands under the oaks. *start from* has it open-grown, young, forest-grown (under taller trees: thin, drawn up, its crown open), wind-swept (low and bowed over, its crown to the lee: *wind-swept* is a slider) and old (thick, hollow, deeply fluted), and *age* goes between young, grown and old. It has about as many triangles as an oak (10,000 to 12,000 grown), though it's a third the height. Left out, said plainly: its thorns, its blossom and its haws; and a hawthorn often has several stems from one foot, where this one always has one trunk.
- **The hazel** is a shrub, not a tree: it has no trunk. Many slender stems rise from one woody foot at the ground (the *stool*), steeply in the middle and leaning out round it, and arch over, so it's about as wide as it's tall: 4 to 6 m. The oak's code grows it as stems: its limbs all leave the stool, each from its own place on it, and none carries the stool on upward. Its panel has *stems* and *stem thickness* where a tree has limbs and a trunk's thickness, and *stool width*; it has no bare trunk, leader or trunk's bends. *start from* has it open-grown, young (a few thin rods), coppiced (cut to the stool seven years ago, as English underwood was for centuries: a sheaf of straight rods), forest-grown (under taller trees: drawn up, its leaves at the top) and old (long uncut: a few thick stems on a wide stool), and *age* goes between young, grown and old. A grown one is about 6,000 triangles. Left out, said plainly: its catkins and nuts; and every stem starts on the stool's top, where a real hazel's also come up from its sides and from the ground beside it.
- **The holly** is a small evergreen tree, grown by the same code as the oak, by its own settings: 8 to 12 m, a dense, very dark pyramid about half as wide as it's tall, on a straight trunk that carries on up through its crown, with branches nearly to the ground; smooth silver-grey bark. It keeps its leaves: in *autumn* it stays green among trees that turn, whatever *needles turn too* says. *start from* has it open-grown, young (a narrow cone, leafy to the ground), forest-grown (under taller trees: thinner, leaning, its crown open) and old (taller, round-topped, its trunk clear low down), and *age* goes between young, grown and old. Its crown has a form (*crown form*, as the beech's): *tiers*, as it starts (each limb's leaves one flat skirt, drawn wider than it grew, the skirts stacked into a dense pyramid with shadow between them), or *cushions*, as it was (rounder clusters, many to a limb). Under taller trees it stays open and uneven, as it was, in no form. A grown one is about 11,400 triangles (10,000 as cushions). Left out, said plainly: its prickles and its berries; and a holly often stands as several stems or in a thicket of its own suckers, where this one always has one trunk.
- **The ash** is a tall tree, grown by the same code as the oak, by its own settings: 22 to 28 m in the open, a domed crown about two thirds as wide as it's tall and more open than an oak's (you see sky through it), its limbs rising steeply, the lower ones sweeping out and turning well up at their tips (*tips turn up*); pale grey bark. *start from* has it open-grown, young (a straight pole with a few rising branches), forest-grown (a long clean pole with a small crown at its top) and old (broader, its lower limbs sweeping low, dead wood in its crown), and *age* goes between young, grown and old. Its crown has a form (*crown form*, as the beech's): *tufts*, as it starts (leaves only at the ends of its branches, where an ash's sit, in bigger clumps, with its wood showing inside), or *cushions*, as it was (smaller clusters all along its branches). A grown one is about 11,000 triangles (12,700 as cushions); an old one about 19,600. Left out, said plainly: its feathered leaves (its tufts are the oak's masses, which cannot show a leaf of several leaflets), its keys, and the pairs its twigs leave in.
- **The birch** is a slim tree, grown by the same code as the oak, by its own settings: 15 to 21 m, a third to a half as wide as it's tall, on a thin trunk that carries on up through a light crown; its limbs rise steeply, arch over, and their ends hang (*tips turn up*, far below 0), so the crown weeps. Its bark is drawn by how thick its wood is: white where it's thicker than a few centimetres, with black marks in streaks, dark purple-brown where it's thinner (so its twigs are dark and a sapling is brown all over), and black at the foot of a thick old trunk. Its leaves are many small clusters, taller than wide. *start from* has it open-grown, young (a thin brown pole), forest-grown (a thin white pole with a small crown at its top) and old (taller, its lower limbs weeping low, its foot black), and *age* goes between young, grown and old. Its crown has a form (*crown form*, as the beech's): *hanging ends*, as it starts (small clusters along its branches, and at each branch's end one that hangs below its twigs, longer than the rest), or *cushions*, as it was (every cluster half again as tall as wide, sitting on its twigs). Its limbs spread and their ends turn down a little; they were turned far further, and the whole limb wept as a willow's does. A grown one is about 6,800 triangles (8,400 as cushions). Left out, said plainly: its catkins and its bark's peeling; and its hanging twigs are not drawn one by one: its limbs' ends are turned down a little and the leaves at them hang. Its clusters are drawn narrower than they grew and carry about two thirds of the leaf the cushions did: a birch's crown is light and half-open.
- **The linden** (the small-leaved linden, *Tilia cordata*: "lime" in England, which has nothing to do with the fruit) is a tall tree, grown by the same code as the oak, by its own settings: 22 to 28 m in the open, a high, dense, egg-shaped crown a little over half as wide as it's tall, on a straight trunk that carries on well up into it; its lower limbs arch out and down and sweep up again at their tips; grey-brown bark, burry on an old trunk. *start from* has it open-grown, young (a neat cone), forest-grown (a tall straight trunk with a narrow crown at its top) and old (broader, its trunk thick, burry and hollow), and *age* goes between young, grown and old. Its crown has a form (*crown form*, as the beech's): *billows*, as it starts (each limb's leaves one big rounded lobe, drawn a little wider than it grew, with clefts between the lobes), or *cushions*, as it was (smaller clusters, many to a limb). A grown one is about 15,300 triangles (14,000 as cushions); an old one about 27,000. Left out, said plainly: its flowers, and the shoots a linden sends up round its foot (a kind grows on a trunk or as stems, not both).
- **Tree**: one tree, or a grid of them to compare (rows × columns, each a different variant or seed, or a row per kind), evenly spaced on flat ground with a metre grid and labels. Double-click a tree in the grid to see it alone.
- **the kind's panel** (both tabs, on the left of the screen): one kind of tree's shape, in a panel of its own. It shows the selected tree's kind: **click a tree** to select it. With none selected it shows the kind the Tree tab shows, or, in the Forest tab, the kind last picked (from a tree, or from the list at the panel's top). Its sliders change every tree of the kind. On each [least, most] row a **red mark** shows what the selected tree drew for itself between the two (in the Tree tab with one tree shown, that tree's), with its number under it: its height, crown width, bare trunk, thickness, big limbs and lean. The workshop's three kinds keep no such values, so they show no marks. Under the shape are the kind's two **greens**, and, in the Forest tab, the kind **in the forest**: its trees all of one age or of several (for a kind with an age), and a sentence saying where it grows (which ground, how much shade), which is the kind's own and has no slider. It holds every setting of the kind's generator, in the same sections for every kind (size, trunk, roots, limbs, crown, movement: those a kind has something in) under plain names; for the workshop's trees, every setting the workshop's generator has, reaching well past the workshop's own sliders (an old oak's girth, a 25 m spruce, limbs hanging past level). A [least, most] setting is one row with two handles; click its values to type them. *start from* gives each kind ready-made shapes: oak, birch, shrub, poplar, baobab; young fir, tall spruce, alpine fir; old pine, stone pine, young pine.
- **season** (the first row of *season and colour*, both tabs): the time of year, from *early spring* to *mid winter*; TreeLab opens in *high summer*. A season is a place to start from, as a kind's age is: it sets three rows in plain sight, each of which can be moved by hand. *leaves on the trees* is how much of their leaves the trees carry: with less than all, clusters of leaves go, each at its own turn, those left are smaller, and the twigs they leave are drawn bare (the trees are grown again that way; at 0 a tree is bare). *new leaves* makes the leaves a pale yellow green, uneven from limb to limb: spring's and early summer's shades of green. *autumn* turns them. Each kind keeps its own time: the hawthorn and the hazel are in leaf first, then birch, beech and oak, and the ash last; in autumn the ash is bare first, and the oak and the beech hold a share of their leaves, brown, into winter. Each tree of a kind is a little ahead of the others or behind. The holly, the firs and the pines keep their leaves. Said plainly: leaves go by whole clusters, not leaf by leaf; the finest twigs of a bare crown are not drawn (only the wood the tree has anyway, and each cluster's own twig); the ground stays as it is; and the workshop's own broadleaf is always grown in full leaf, with only its colour following the season.
- **season and colour** (both tabs): *autumn* turns the broadleaves from green through gold to red, each tree at its own pace and limb by limb, in maple, birch, oak, beech or mixed colours; firs and pines stay green unless *needles turn too*, and a holly always. Each kind's two greens are colour pickers in the kind's own panel.
- **Forest**: the trees planted on generated hills.
  - **forest**: where they stand (a seed, and *new layout*), the area (a circle of radius R, or a square), and seeds per hectare (10 to 3,000: how many places a tree may grow; *where trees grow* decides which do, and *holds* says how many stand), up to 160 m from the middle. The hills grow with the forest. A forest holds at most 4,000 trees: a bigger, denser one is planted thinner all over, and says so. The numbers under the title include its *canopy cover*, the share of the ground under a crown: a closed wood is about 85 to 95% covered, and the sun reaches the floor through the rest. The workshop's wind covers the middle 80 m with its gusts; further out the trees feel a steady wind.
  - **pattern**: *even spacing* (no two closer than about ¾ of the average spacing; the default), *random*, *jittered grid* (the workshop's own), *clumps*, or *rows* (a plantation, at an angle).
  - **groves and clearings**: noise splits the area, and trees grow only in the groves.
  - **mix**: a table, one row a kind, the kinds in their groups (an English wood, the workshop's first trees). A row is a tick (whether the kind grows), its name, a bar and a number for its share, and how many of it stand in the forest as planted. A click on a kind's name shows that kind in the panel on the left. *set the mix* chooses how a share is counted: *by count*, a kind's share of the seeds that fall, or *by cover*, where the kinds are listed under the canopy and the underwood, each layer has a bar for how much of the ground its crowns cover, a kind's share is its share of its layer's crowns, and each row says what stands beside what was asked. *a wood of* starts from a ready-made mix by cover (oak over hazel, beech wood, birch and oak on high ground). Under the table: *mixed* or *in stands* (each kind in its own patches), how many variants a kind, and the sizes.
  - **ground**: which hills, how high and wide, how rough, and the steepest slope a tree grows on.
  - **Roots on the hills.** TreeLab's own kinds stand on the ground they are planted on: each tree's roots run over the ground under it, and its trunk is sunk just so far that the downhill side of its foot is in the ground (on level ground, not at all). On a slope a tree dams the loose ground above it and the ground below it is carried off, so its roots lie a little deeper uphill and a little prouder downhill. Said plainly: the ground only drapes a root, setting how high it lies; where it runs and where it forks are grown as on level ground. The rule for uphill and downhill is a rule of thumb, at half strength, so the uphill roots aren't lost. A leaning tree's roots don't lean with it. Roots are drawn for the trees nearest the middle first, up to 600,000 triangles of them (about 1,400 oaks, or 500 ancient oaks); a tree further out stands without them, and the numbers under the title say so. The workshop's trees are sunk 0.3 m, as before. The Tree tab's ground is level, so a tree there is drawn as it was grown.
  - *walk among the trees* puts the figure in the forest, a little back from its middle, where the trunks leave room, facing the sun, and the camera behind it. **W A S D** or the arrow keys walk it, the way the camera looks; **Shift** runs; **Space** jumps. A game pad works too: the left stick walks, the right stick looks round, the right trigger runs (as far as it's squeezed) and A jumps. Drag to turn the camera round the figure; the wheel brings it nearer or further. It walks at 1.4 m a second and runs at 4.2, and takes a moment to get there and to stop; slopes slow it as they slow a walker (Tobler's hiking function: fastest a little downhill, slower the steeper it is either way); a jump lifts it 45 cm and is left to gravity; trunks stop it and it slides round them. Its limbs are moved by cycles keyed by hand (standing, a walk, a run and a jump), or by clips of your own fitted to the figure, if you make some (see below), played as fast as it goes over the ground so that its feet don't slide, and each foot is put on the ground where it is: higher on the uphill side, tilted with the slope, the hips sinking as far as the lower foot needs. What isn't as in life: the feet aren't held where they landed (between a walk and a run they slide a little), nothing knows about balance, and the camera goes through leaves and trunks. *through its eyes* sees the forest from the figure's own eyes instead (1.7 m up; the figure isn't drawn): there a drag looks round, up into the crowns too, and the wheel and a drag with two fingers or the right button walk as well. Untick *walk among the trees* to go back above the forest; a link or a settings file keeps all of it.
  - **where trees grow**: three rules decide which seeds become trees, each a slider from 0 (off). *each kind to its ground*: every kind has a stretch of the hills it likes, from their lowest ground to their highest, and is given fewer of the places elsewhere: the ash keeps to the lower slopes, the birch and the pines to the higher ground, the hawthorn grows anywhere (on flat ground it changes nothing). *room between trees*: two trees of about a height stand no nearer than a little over half of their two crowns' reach, as crowns in a wood touch and interlock; the taller was there first, and a small tree under a tall one need only be clear of its trunk. *light under the crowns*: under a taller tree's crown a tree lives by how much shade its kind bears: a holly or a beech grows there, a hazel mostly, a birch, a pine or an ash hardly ever. The stats say how many were crowded out and shaded out. The mix's shares are of the seeds: a kind with a wide crown loses more of its own. With all three at 0 the forest is planted as it was before there were rules, and a link made before them opens that way. Said plainly: these are rules of thumb for a planted picture, not a wood growing up over years: nothing seeds or dies, a tree's shape doesn't answer to its neighbours (a kind's *forest-grown* shape is chosen by hand), and the ground is only its height: there is no water, soil or aspect.
  - The forest is grown from the Tree tab's seed and shapes: change a kind's shape and the forest's trees change too. Double-click a forest tree to see it alone in the Tree tab.
- **view** (both tabs): *turn slowly* turns the view round the trees by itself, at *turn speed* degrees a second (12 is a turn in half a minute; below 0 it turns the other way). **A click** on a tree selects it (a click, not a drag; Shift and a click works too): a ring marks its foot, a note says what it is, and the panel on the left turns to its kind. A click on no tree lets it go. *centre on the selected tree* (or **C**) slides the view so that tree is at the middle of the screen, from the same angle and distance, and the view turns round it from then on; with no tree selected it centres on the middle of what's shown. **Esc** lets the tree go. A selection isn't a setting: a link doesn't carry it. Walking among the trees, the view stays with the figure.
- **light** (both tabs): the time of day, from 5:00 to 21:00, and which way the noon sun shines from. *time runs* lets the day run, so many hours of it for each minute you watch (after 21:00 it is 5:00 again: there is no night; P pauses it): the sun moves every frame, and the sky's own light is measured again five times a second. The sun crosses a real sky, turns golden and dims as it sinks; the haze over the horizon takes the sky's colour in whichever direction you look. The sky is drawn as bright as the light it gives, no brighter: a clear sky gives level ground about an eighth as much as the sun gives a surface facing it (a quarter at sunset), so against sunlit ground it is a mid blue, as in a photograph exposed for the ground. Everything takes its light from the sky as drawn, and from below what the sunlit ground throws back: the shade is deeper than a pale sky would make it, and bluer. The camera's exposure puts a white thing in the noon sun just short of white. Shadows are sharpest near the camera and fitted to what's shown, so the trees close by cast crisp shadows even in a 160 m forest. Leaves deep in a crown are darker than those outside it, and looking toward the sun, the crowns' edges glow: *sun through leaves* sets how much (0 to 2). The air among the trees catches the sun where nothing shades it, so the light falls in shafts between the trunks; as in life, they show best looking toward the sun, against shade (*light shafts*: 1 as in life, where from the side they're faint; above 1 is a boost, named as one: the air shows the sun it catches up to 10 times as brightly). The sun is a disc, not a point, so a beam is sharp just under the gap that lets it through and softer the further it falls (9 mm for each metre): small gaps high in the crowns give a glow far below, not lines. The same on the ground: the spots of sun on the floor of a wood are round and soft, a trunk's shadow at its foot crisp. *mist and fog* lays water drops on the ground: mist while you see 1 km or more through them, fog under that (the two are one thing at two strengths; haze is another, the dry air of a clear day). From clear air through a thin mist (0.2: you see 2.4 km) and the line between the two (0.31: 1 km) to thick fog (1: about 100 m): thick in banks and thin between, with wisps, lying over the hills, drifting with the wind and changing as it goes. It dims what's behind it, catches the sun where no tree shades it, and under the trees takes only the sky's light that gets down to it. Its drops throw light as real ones do (10 micrometres across: about half almost straight on, the rest mostly forward), so mist is brightest by far looking toward the sun; light turned aside again and again fills sunlit mist from every side, so from the side it is white, not dark. The sun on the ground and the trees in the mist is dimmer for it, and the mist's soft light falls on them in its place. *gaps in the crowns* lets the sun through the foliage in spots, so the shade is dappled, the leaves inside catch the sun, and shafts fall through (0 solid shade, 1 thin crowns). The trees keep the sky's light off what's under them as well as the sun's: under a closed canopy the floor, the trunks and the crowns' undersides are dim, and the spots of sun stand out (*shade under the trees*, 1 as worked out from the trees, 0 none). And the eye adjusts to what it looks at: among the trees it opens up, so the shade shows and the sun and the shafts burn bright; back in the open it closes down again. It makes up for a little darkness wholly and for a lot only partly, and opens furthest where the shade is deepest against the open: about three stops in a wood on a misty morning, a little over two in the same wood at noon (*eye adjusts to the view*, 1 as far as an eye goes, 0 the hour's exposure only). TreeLab opens at 19:15, the sun low and to one side.
- **sway** and **wind**: the workshop's sway and wind. The hills shelter what's behind them, and the wind is calmer under the crowns. *show wind (V)* draws it. P pauses.
- **save and share**:
  - *save settings to a file* and *load settings from a file*: a `.json` file with every setting. The browser also keeps your last settings, and the address always holds a link to what you see.
  - *copy a link to this view*: the link opens TreeLab on exactly these trees.
  - *take a screenshot*: a PNG at 1×, 2× or 4× the screen, with or without "TreeLab · Studio Gray Lake" in the corner. *share a screenshot…* opens the system's share sheet where the browser has one; otherwise it downloads the picture and offers the link for X, Bluesky, Reddit or Facebook.
  - *download the model (.glb)*: the trees shown, standing still, flat-shaded as on screen, with the forest's ground cut to the forest if you like. *Instanced* is smallest and uses glTF's `EXT_mesh_gpu_instancing` (three.js, Babylon.js, Blender 3.6 and later, Unity with glTFast). Godot 4.6 can't open it: choose *one node a tree*, which works in every glTF tool. The file carries its settings and link.

Beside its name TreeLab says which TreeLab it is, so a picture, a link or a fault can be matched to the code that made it: its version and the day it was built (the website's: `0.3.0 · 2026-11-11`), or, in a git checkout, the commit it was built from (`0.3.0 · 18d23c1`); on the dev server it says so, with a `+` when there is work not yet committed (`0.3.0 · dev · 18d23c1+`). Hover over it for the same in a sentence. A build made for the website names no commit. Click it for the feature log: what each release brought, newest first, with its day and a link to its news post where it has one (`src/changelog.js`; a release adds its entry at the top, and a test holds the top entry to the version in `package.json`). The card's last line links to the studio's news.

A first visit opens with a welcome card: what TreeLab is, how to look round, a link to the studio's news post about it, and on a phone a line saying it works best on a computer. *OK* (or Enter, or Escape) closes it until the next visit; *Don't show this again* is kept in your browser only, so where the browser keeps nothing the card shows again. A share link opens straight on its view, without the card.

Each part of the panel has a washed-out colour of its own (trunk, roots, limbs, crown; light, wind, view), so one tells from the next. A row is its name, a bar and a small box for the number: a long name wraps onto more lines and the bar keeps its length. Drag a card's inner edge to make it wider or narrower (the arrow keys move a focused edge; a double-click puts it back). The cards fold away to their top row: each by the button in its corner, all by **H** (and H again brings them back); which are folded is kept in your browser only. Every row has a tooltip: hover it, focus it, or tap its name on a phone. *view → text size* sets the text from 1× to 2× (1.5× to start); it's kept in your browser only.

Settings files and links from older or newer TreeLabs still load: settings TreeLab doesn't know are left out, missing ones take their defaults, and every value is kept within its slider.

What TreeLab holds to, and what it will not become, is in [docs/FOUNDATIONS.md](docs/FOUNDATIONS.md); how its parts fit, how to add a kind of tree, and the rule for links are in [docs/DESIGN.md](docs/DESIGN.md).

A link is short, and plain text after `#v=`: it names what the settings start from (a starting view, a kind's ready-made shape, or nothing: the defaults) and lists only what differs, as in `#v=1-misty.wood~light_hour-7.5_mist-.6`. It holds only letters, digits and `-` `_` `.` `~`, so chats, emails and markdown leave it whole. A link opens as it was made, always. The first number is the link's version, and what links of each version start from (every default, every starting view, every ready-made shape) is recorded once in `src/frozen` and never edited; a link is read against its own version's record, so retuning a view or a default later leaves the links already made as they were. Whenever any of that changes the version goes up and `npm run freeze` records the new one (a test fails until then). The longer links TreeLab made up to 0.3.1 (`#s=`) still open, as 0.3.1 opened them. What is kept is the settings: where the code that grows a tree from its settings changes, the same settings grow it as today's TreeLab does.
